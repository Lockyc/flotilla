# flotilla — agent notes

macOS-only Tauri v2 app (Rust + a static web frontend in `src/`) in the same family as curator, warden and lector. A workspace where any tab can head a group of documents (usually a Google Drive folder); documents opened from it list beneath it, each is open once, and the session restores on relaunch.

## Layout

- `crates/flotilla-core` — platform-neutral, Tauri-free core: `identity` (document keys), `model` (groups, one-copy registry, Recent), `nav` (what each navigation does), `session` (the session file).
- `src-tauri` — the Tauri shell: `state` (`AppState` and its lock rule), `tabs` (content webviews `main:<TabId>`, the `intercept` hook, `sync`), `sidebar` (the chrome DTO), `detach` (popped-out tabs: one shell-core detached window per `detached` tab, labelled from the tab id so geometry persists; its page keeps the `main:<TabId>` label, which `tabs::own_webview` keeps the main window from touching), `commands`, `menu` (the menu bar; the Group menu and the row context menu share `menu_state_for`; a DTO push rebuilds the menu bar only when its `MenuState` changed), `persist` (debounced save to `session.json` in the app data dir). Plus `build.rs`, `tauri.conf.json`, `capabilities/`.
- Every workspace change ends in `tabs::changed`: the pure `tabs::plan` decides which webviews to close, create (only ever the active tab's, which is what keeps restore lazy), show and hide; then the pure `detach::plan` decides which popped-out windows to open and close (every `detached` tab has one, so relaunch reopens them), the DTO is pushed and a save scheduled. An operation that raises a tab goes through `detach::raising`: a popped-out tab's window is raised and the main window keeps what it showed.
- `src/` — the chrome page; `chrome.js` binds chrome-core's `ChromeSidebar` to the Rust commands. `chrome-core.{css,js}` are generated by `build.rs`, git-ignored.
- `scripts/tooling.env` — per-app parameters for shell-core's release scripts, which `build.rs` materializes (git-ignored).

## Shared cores

chrome-core and shell-core are pinned by `rev` in `src-tauri/Cargo.toml`; shell-core also in `crates/flotilla-core/Cargo.toml`, all its dep lines at one rev (`scripts/tooling.env`'s CORES lists both manifests, so `shell-pin` rewrites both). Local-dev loop: `just chrome-dev` / `shell-dev`, re-pin with `chrome-pin` / `shell-pin`; the `[patch]` lines in the root `Cargo.toml` stay commented in git (`just gate` and `.githooks/pre-commit` refuse otherwise). The toolchain is pinned in `rust-toolchain.toml`, in lockstep with the sibling apps.

## Commands

`just run`, `just test`, `just gate` (the check; there is no CI), `just build`, `just install`.

## Releases

Version source of truth is `src-tauri/Cargo.toml`; tag `v<version>`, GitHub release with notes. The updater private key lives at `~/.tauri/flotilla-updater.key` (never committed); its public half is `plugins.updater.pubkey` in `tauri.conf.json`. `createUpdaterArtifacts` is enabled only by shell-core's `scripts/release.sh`, never in the committed config, so keyless from-source builds work.
