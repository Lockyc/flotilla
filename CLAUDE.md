# flotilla — agent notes

macOS-only Tauri v2 app (Rust + a static web frontend in `src/`) in the same family as curator, warden and lector. A workspace where any tab can head a group of documents (usually a Google Drive folder); documents opened from it list beneath it, each is open once, and the session restores on relaunch. Early: the window mounts an empty chrome.

## Layout

- `crates/flotilla-core` — platform-neutral model (empty so far).
- `src-tauri` — the Tauri shell (`lib.rs`, `build.rs`, `tauri.conf.json`, `capabilities/`).
- `src/` — the chrome page; `chrome.js` binds chrome-core's `ChromeSidebar` to the Rust commands. `chrome-core.{css,js}` are generated by `build.rs`, git-ignored.
- `scripts/tooling.env` — per-app parameters for shell-core's release scripts, which `build.rs` materializes (git-ignored).

## Shared cores

chrome-core and shell-core are pinned by `rev` in `src-tauri/Cargo.toml` (shell-core's build-dep and runtime dep in lockstep). Local-dev loop: `just chrome-dev` / `shell-dev`, re-pin with `chrome-pin` / `shell-pin`; the `[patch]` lines in the root `Cargo.toml` stay commented in git (`just gate` and `.githooks/pre-commit` refuse otherwise). The toolchain is pinned in `rust-toolchain.toml`, in lockstep with the sibling apps.

## Commands

`just run`, `just test`, `just gate` (the check; there is no CI), `just build`, `just install`.

## Releases

Version source of truth is `src-tauri/Cargo.toml`; tag `v<version>`, GitHub release with notes. The updater private key lives at `~/.tauri/flotilla-updater.key` (never committed); its public half is `plugins.updater.pubkey` in `tauri.conf.json`. `createUpdaterArtifacts` is enabled only by shell-core's `scripts/release.sh`, never in the committed config, so keyless from-source builds work.
